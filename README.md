# FFXIV Tradecraft Leve Planner 0.3

Небольшое настольное Python-приложение с русским интерфейсом. Сравнивает покупку готовых HQ/NQ предметов и крафт из покупных ингредиентов; рассчитывает серию одного leve до следующего уровня, кратного пяти.

## Маршрут до желаемого уровня

Кнопка **«Маршрут прокачки…»** открывает отдельное окно. Основной расчёт до следующего пятиуровневого рубежа остаётся прежним, его результаты и параметры не меняются.

В новом окне выберите профессию, мир/DC, текущий и желаемый уровни (например, **1 → 50**), EXP внутри текущего уровня и доступные allowances. Пустой бюджет означает отсутствие лимита. Можно выбрать покупку/крафт, NQ/HQ и приоритет **«Дешевле закупка»** или **«Меньше allowances»**. Для HQ-крафта нужна гарантия получения HQ.

Маршрут показывает этапы, выбранный leve и место получения, количество принятий и сдач, allowances, нужный и полученный EXP, остаток EXP, расходы, gil-награды и баланс. Выбор этапа открывает предметы, рецепты, закупку целыми стаками и кликабельные ссылки Universalis. Итог и этапы экспортируются в CSV.

Расчёт переходит к новым заданиям при открытии очередного уровня leves (включая уровни 52/54 и другие), учитывает EXP сверх рубежа и переносит купленные или скрафченные остатки. Один рыночный стак резервируется только один раз на весь маршрут. Крафт использует только рецепты, доступные на начале этапа; EXP самого крафта не добавляется.

Выбор поэтапный: сравниваются ближайшие уровни заданий, а старые рассматриваются, если ближайшие нельзя оценить. Это рекомендация, **не доказательство глобально минимальной стоимости**. Все цены относятся к текущему снимку рынка. Дорога начисляется на каждый этап; бюджет сравнивается с закупкой всей серии заранее, gil-награды не финансируют закупку. Если цен или стаков не хватает, сохраняется рассчитанная часть, а полная стоимость до цели показывается как неизвестная. Недостаток бюджета и allowances выводится явно.

Для маршрута с Lv 1 ремесленника leves должны быть уже открыты на персонаже. Квесты открытия, координаты NPC, реальные перемещения, временные затраты, инвентарь до начала маршрута и ремонт не моделируются.

## Список крафта для Teamcraft / Artisan

После расчёта маршрута нажмите **«Список крафта…»**. Откроется отдельное окно с полями **List Name**, **Pre-craft Items** и **Final Items**, кнопками копирования и сохранением TXT. Выберите весь маршрут или заранее выделенный этап; можно включить **все предметы для сдачи** либо **только крафт, запланированный маршрутом**.

При включённом **«Крафтить полуфабрикаты»** рецепты раскрываются рекурсивно: общие материалы суммируются до округления выхода рецепта. Полуфабрикаты идут в порядке изготовления. Базовые ресурсы и кристаллы перечислены ниже как материалы для закупки/сбора. Предмет, который одновременно нужен для сдачи и как ингредиент, включается в Pre-craft Items одним общим объёмом.

Пример для трёх Peisteskin Cesti:

```text
Pre crafts :
3x Steel Ingot
3x Peiste Leather
```

```text
Items :
3x Peisteskin Cesti
```

В Artisan откройте **Crafting Lists → Teamcraft Lists → Import** и вставьте имя и каждый блок в соответствующее поле. Этот формат передаёт **количество предметов**, а импорт рассчитывает число крафтов по выходу рецепта. Формат сверяется с [исходным кодом импорта Artisan](https://github.com/PunishXIV/Artisan/blob/main/Artisan/CraftingList/Teamcraft.cs).

Названия предметов — английские, для клиента EN. Текст не передаёт HQ/NQ, recipe ID или выбранную профессию для предметов с несколькими рецептами. Для HQ отключите **Final Items → Import as Quick Synth** и настройте HQ в Artisan. Требования качества и уровней указаны в нижней части окна; другие ремесленные профессии и книги не считаются автоматически открытыми. Начальный инвентарь не вычитается. Полный маршрут крафтите по этапам — более высокие рецепты ещё могут быть недоступны.

Стоимость и EXP маршрута при экспорте не пересчитываются. В режиме «Все предметы для сдачи» готовые покупки заменяются списком крафта; изготовление полуфабрикатов также меняет закупку. Неполный маршрут экспортирует только рассчитанные этапы. Предметы без обычного рецепта остаются в списке закупки с пояснением.

Каталог дополнен цепочками ингредиентов из того же закреплённого commit игровых таблиц: **1 250 рецептов и 1 793 предмета**. Награды и набор leves сохранены. Обновление каталога поддерживает эти цепочки; старый кэш с ограниченными рецептами заменяется встроенным расширенным снимком при расчёте.

## Обновления программы

При обычном запуске в фоне проверяется последний стабильный релиз публичного GitHub-репозитория. Токен не нужен. Внизу окна есть статус, **«Проверить обновление»** и **«Открыть релизы ↗»**. Сбой сети или лимит API не мешает работе программы. В DEMO автоматическая проверка отключена.

Новый ZIP устанавливайте вручную после закрытия приложения, распаковывая вместо прежних файлов. Проверка версии программы не обновляет цены Universalis и игровой каталог.

## Запуск

Требуется **Python 3.10+ с Tkinter**. В обычной установке Python для Windows Tkinter уже включён. Сторонних библиотек, ключей API и аккаунтов не нужно; `requirements.txt` оставлен для явного описания зависимостей.

1. Распакуйте архив в папку, доступную для записи.
2. В Windows запустите **`start.bat`** двойным щелчком. Или выполните из папки приложения:

   ```text
   python run.py
   ```

3. Выберите профессию, мир или DC; введите текущий уровень, EXP **внутри этого уровня**, бюджет и доступные allowances.
4. Нажмите **«Найти выгодные leves»**. Выберите строку: снизу появятся предметы для сдачи, рецепты, количества ингредиентов, конкретные стаки и миры для закупки.

В Linux для окна может потребоваться системный пакет `python3-tk`. На macOS нужен Python с работающим Tk. Команда `python -m tkinter` позволяет проверить установку.

Оффлайн-пример интерфейса:

```text
python run.py --demo
```

В DEMO все цены искусственные и помечены соответствующим образом. Обычный запуск использует Universalis; демонстрационные цены не подставляются при сбоях API.

## Что показывает приложение

- Все восемь профессий: Carpenter, Blacksmith, Armorer, Goldsmith, Leatherworker, Weaver, Alchemist, Culinarian.
- Следующий рубеж: 1→5, 5→10, 52→55, 99→100. На максимальном уровне расчёт прокачки не выполняется.
- По умолчанию — текущая и предыдущая группы по пять уровней. **Промежуточные tiers 52/54/56 и т. п. сохранены**, а не округлены до пяти. Опция «Все доступные уровни» включает более ранние задания и увеличивает число запросов.
- Варианты NQ/HQ покупки и NQ крафта. HQ-крафт появляется после включения «Могу гарантированно крафтить HQ».
- После изменения галочки HQ нужно снова нажать **«Найти выгодные leves»**. Если выбран фильтр «Крафт + HQ», а этот вариант не был рассчитан, окно объясняет, как его включить.
- Количество принятий задания, фактических сдач, allowances, полный расход, gil-награду и баланс. **Расходы показываются с «−», награды с «+»; положительный баланс означает прибыль, отрицательный — убыток.**
- Возможность выгрузить видимые результаты с текущими фильтрами и сортировкой в CSV с UTF-8 BOM для Excel.

**Приоритет:** выберите «Максимальная прибыль», «Дешевле закупка», «Меньше принятий leve», «Меньше allowances» или «Меньше сдач». По умолчанию — максимальный баланс на достижение рубежа. «Дешевле закупка» сравнивает сумму, которую нужно заплатить заранее; «Максимальная прибыль» учитывает также gil-награду.

Нажатие на **любой заголовок столбца** сортирует по нему; повторное нажатие меняет направление (▲/▼). Числа сортируются по значению, а не по тексту. Расходы сортируются по размеру закупки, несмотря на отображаемый знак «−». Доступные планы идут первыми; неизвестные суммы — в конце в обоих направлениях. При равенстве — меньше allowances и сдач.

**Фильтры:** способ (покупка/крафт), качество (HQ/NQ), «Только доступные» и поиск по названию. Фильтры и сортировка применяются сразу к рассчитанным вариантам и не запрашивают новые цены. «Сброс» возвращает все строки и приоритет по прибыли. Все другие варианты доступны с объяснением ограничений; если нет доступного плана, приложение не выдаёт такой вариант за выполнимый.

## Данные и обновление

Каталог и рецепты получены из [xivapi/ffxiv-datamining](https://github.com/xivapi/ffxiv-datamining), содержащего извлечённые игровые таблицы. Это общественный проект, а не официальный API Square Enix. Сборщик читает `csv/en`:

| Таблица | Использование |
| --- | --- |
| `Leve` | Уровень, профессия, базовые EXP/gil, `AllowanceCost`, место получения |
| `CraftLeve` | Все четыре слота предметов, количества, `Repeats` |
| `Recipe` | Профессия, выход рецепта, все восемь слотов ингредиентов, включая кристаллы |
| `RecipeLevelTable` | Настоящий уровень рецепта вместо внутреннего ID |
| `Item` | Названия, HQ и возможность рыночной продажи |
| `ParamGrow` | EXP до следующего уровня |
| `PlaceName` | Названия мест |

В комплекте — **1 120 leves, 1 250 рецептов и 1 793 предмета**, уровни прокачки 1–100. Снимок leves собран **11 октября 2026**, цепочки ингредиентов добавлены **12 октября 2026** из того же изменения английских таблиц: `7.56h1 (#118)`, 17 сентября 2026, commit `d71de329cc6ed30c6fb16b9108cdf7d29c653302`. Метаданные записаны в `data/catalog.json` и отображаются в окне.

Сборщик сначала получает последний commit, затрагивающий `csv/en`, затем скачивает **все таблицы из одного commit**. Это предотвращает смешивание разных версий. Проверяет структуру, наличие профессий, предметов, положительных наград и полной таблицы EXP. Готовый каталог заменяется атомарно только после проверки.

При расчёте снимок проверяется/обновляется, если последняя успешная проверка была более семи дней назад. Кнопка **«Обновить игровые данные»** принудительно обновляет каталог; требует примерно 25 МБ загрузки. Для консоли:

```text
python run.py --refresh
```

При сбое сохраняется предыдущий проверенный каталог, а окно показывает предупреждение. Актуальность ограничена последними опубликованными данными источника; обновление приложения не создаёт сведения, ещё не извлечённые сообществом.

Миры/DC получаются через Universalis и кэшируются на сутки. Есть встроенный список на случай недоступности API. Интерфейс предлагает **глобальные регионы Japan, Europe, North-America, Oceania**: английский каталог соответствует глобальному клиенту. Китайские и корейские версии могут иметь другой патч и не включены.

## Рыночные цены

[Документация Universalis](https://docs.universalis.app/) и [исходный код V2 API](https://github.com/Universalis-FFXIV/Universalis/blob/v2/src/Universalis.Application/Controllers/V2/CurrentlyShownController.cs).

Используются `GET /api/v2/worlds`, `/data-centers`, `/{world-or-dc}/{itemIds}`. Предметы запрашиваются пакетами до 50 ID, отдельно NQ и HQ, с `entries=0` и `listings=100`. Передаётся User-Agent приложения. Манекенные объявления исключаются. История продаж, средние цены и NQ не заменяют отсутствующие HQ-предложения.

**Покупается весь стак.** Например, предложение «1 gil × 99» стоит 99 gil даже для одной нужной штуки. Алгоритм перебирает комбинации стаков с помощью точного 0/1 dynamic programming и находит минимальную сумму для покрытия требуемого количества. Каждый listing можно использовать только один раз. Стак меньшего размера с большей ценой за единицу может оказаться выгоднее.

Оптимум считается **среди полученных первых 100 предложений каждого качества**, а не среди всех предложений игрового рынка. Недостаток количества означает недостаток в полученной выборке. Другие предложения, посещение NPC-магазина или собственные запасы могут улучшить результат.

Налог покупателя задаётся в интерфейсе, по умолчанию 5%; округляется вниз на каждый стак. Введите 0 для покупок без налога. Дополнительные затраты на дорогу задаются одной суммой на весь план.

Universalis обновляется игроками и не гарантирует наличие объявления к моменту покупки. В деталях показаны мир и дата последней проверки каждого стака; обновления старше суток отмечаются предупреждением. Рынок DC предполагает возможность поездок между мирами.

## Формулы и механика

- HQ-сдача: `EXP = base_EXP × 2`, `gil = base_gil × 2`. Все предметы сдачи считаются одного качества; смешанная сдача HQ/NQ не моделируется.
- Для старых expansion leves после соответствующего рубежа 50/60/70/80/90 применяется cap **1 000 EXP за сдачу**, после HQ-множителя. Правило пересчитывается после каждого полученного уровня, включая переход посреди серии. Ограничения 80/90 описаны в [официальных заметках 6.0](https://na.finalfantasyxiv.com/lodestone/topics/detail/bdd208b52ddababad086dc9679e96a8412962edf/) и [7.0](https://na.finalfantasyxiv.com/lodestone/topics/detail/c807875c5f8f7529887c86d2955f709eae0231ef).
- Сдач на принятие — от 1 до `1 + CraftLeve.Repeats`: обычные, triple turn-in и large-scale до шести сдач. Приложение сравнивает эти варианты. Последнее принятие использует только сдачи, нужные для достижения цели.
- `allowances = число_принятий × Leve.AllowanceCost`. Повторные сдачи не требуют новых allowances. Large-scale leves расходуют 10 на принятие; соответствующие слоты предметов суммируются (например, три одинаковых копья).
- `crafts = ceil(нужные_предметы / AmountResult)`. Для каждого ингредиента: `AmountIngredient × crafts`. Округление выполняется для **всей серии**, поэтому выход из трёх предметов корректно используется для нескольких сдач.
- При наличии нескольких подходящих рецептов выбирается наиболее дешёвый вариант для полного плана. Покупаются NQ-ингредиенты, включая готовые промежуточные материалы, шарды/кристаллы/кластеры.
- `расход = −(покупка_целых_стаков_с_налогом + дорога)`; `баланс = gil_за_фактические_сдачи + расход`. Например: расход −2 992, награда +7 714, баланс **+4 722 gil**.
- Бюджет должен покрывать **закупку всей серии заранее**. Реинвестирование gil-наград и продажа остатков не учтены. Allowances — текущий запас 0–100; при нехватке показано количество пополнений по 3, точная дата доступности не вычисляется.

## Границы расчёта

Основное окно сравнивает **серии одного задания**, доступного сейчас, до ближайшего рубежа. После рубежа укажите новый уровень/EXP и пересчитайте цены. Для переключения заданий по мере повышения уровня и произвольной цели до 100 используйте отдельное окно «Маршрут прокачки»; его поэтапный алгоритм не гарантирует глобальный минимум стоимости.

Крафт рассматривает обычные рецепты выбранной профессии до `текущий уровень + 5`; рецепты с книгой, специализацией, квестовые и expert исключены. Возможность выполнить рецепт зависит от экипировки и открытого Crafting Log. Уровень и ID рецепта отображаются. HQ-крафт предполагает гарантированный HQ-результат; вероятность, ротации и неудачные крафты не рассчитываются.

Не учитываются самостоятельный сбор, рекурсивный крафт промежуточных материалов, NPC-магазины, инвентарь, время, ремонт, случайные награды предметами, EXP самого крафта и Challenge Log. Число сдач поэтому может быть больше фактически нужного при дополнительном опыте. Gil из игровых таблиц — базовая оценка; фактическая награда может отличаться. Разблокировку leve/NPC/регионов проверяет игрок.

Есть защитный предел **20 000 единиц одного покупаемого предмета**: такие планы помечаются ограничением, а не считаются по упрощённой формуле. Кнопка «Все доступные уровни» может показывать много непрактичных старых заданий.

## Кэш и ошибки

Папка `cache/` создаётся рядом с приложением; аккаунты и персональные данные не нужны.

- Рыночные ответы: TTL 15 минут. При сбое API разрешён старый локальный ответ не старше 48 часов **с предупреждением**.
- Миры/DC: TTL сутки; устаревший кэш допустим до 30 дней, затем встроенный список.
- Для 429, сетевых сбоев и 500/502/503/504 — до трёх попыток с короткой задержкой. Для 400/403/404 повторные запросы не выполняются.
- Проверка JSON и структуры до записи. Повреждённый кэш игнорируется. Запись атомарная.
- Нет цены, неразрешённый ID, API offline, пустые предложения или недостаточный объём — **неизвестная стоимость**, не бесплатный ингредиент. Такой план не становится доступной рекомендацией.
- Сеть и расчёты работают в отдельном потоке; окно остаётся отзывчивым.

```text
python -m unittest discover -s tests -v
```

CLI печатает первые 10 вариантов в JSON. `--scope` принимает имя DC либо имя/ID мира из встроенного глобального списка; `--tax`, `--travel`, `--craft-hq` управляют теми же допущениями. В режиме CLI каталог обновляется явно через `--refresh`; в окне — также автоматически.

Тесты включают сравнение алгоритма стаков с исчерпывающим перебором, границы EXP, HQ, повторные сдачи, бюджет/allowances, выход и ингредиенты рецептов, плохие ответы API, TTL/retries, все профессии на каждом пятиуровневом рубеже и создание окна с асинхронным DEMO-расчётом. GUI-тест пропускается только на системах без доступного Tk/display. Подробности проверки этой сборки — в `VALIDATION.md`.

В GitHub Actions настроена автоматическая проверка на Windows с Python 3.10, 3.12 и 3.14 при push, pull request и ручном запуске. API-ключи для тестов не нужны; рыночные данные в тестах искусственные.

## Файлы

`run.py` — запуск; `start.bat` — Windows; `leveplanner/` — интерфейс, HTTP, каталог, рынок и расчёты; `data/` — проверенный снимок и миры; `tests/` — автоматические проверки; `requirements.txt` — зависимости. Кэш и пользовательские CSV не входят в архив.

Приложение не взаимодействует с клиентом игры и не выполняет задания. Игровые названия и данные принадлежат Square Enix. Авторы источников: xivapi/ffxiv-datamining и Universalis-FFXIV.
